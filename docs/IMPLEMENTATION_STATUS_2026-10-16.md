# 当前实现与检查结果

| 项目 | 当前行为 |
|---|---|
| 插件边界 | 插件使用 Context 公开接口，跨插件访问继续检查 requires；插件目录没有私有 harness 访问。 |
| conclude | 引语和回执绑定、复核、交付、保存分开；回执联合覆盖在 core 中计算。 |

| 存储 | SQLite 在事务里只写新增或变化行，旧 JSON 导入有去重与删除标记；事件继续保存在 jsonl。 |

| 变化对照 | 原文旧／新双栏显示差异，支持精确版本读取和逐节点准备修订请求。 |

## 有界检查

检查按实际变化选取，没有在每次提交后重新跑全套。参数交付、阶段模型选择、日志授权与只读行为、脚注重启和版本冲突、基础回执／迁移／恢复路径的针对性检查通过。前端原有 19 项与四条离线 smoke 通过；新增日志会话切换及双栏／逐节点交互各有一项行为检查。

全量基线在要求压缩验证后停止，没有全量通过结论。新增测试涉及的失败修正后，仅重跑失败项或相关组。Windows 沙盒阻塞 TestClient 的本地 socketpair，相关小组在允许本地事件循环的执行环境中完成；业务测试仍阻断外部网络。

## checkpoint 开销

用两份隔离的合成会话，各包含 100 或 1000 条材料，每条 20000 字符，并有对应历史卡片和回执。每份会话测三次新增材料、卡片和回执的 checkpoint，取中位数。对照为同一会话整包 JSON 的重新编码和写入。

| 初始材料数 | SQLite checkpoint | 整包 JSON 对照 | 每步变化行 |
|---|---:|---:|---:|
| 100 | 2.00 ms | 13.58 ms | 4 |
| 1000 | 15.54 ms | 117.55 ms | 4 |

这是当前机器上的小型测量，不能外推到多用户服务。SQLite 避免了重写完整材料，仍会扫描部分历史和元数据；本次不再增加存储抽象或重构这段扫描。原始结果在 `.chatbox-runtime/checkpoint_probe_results.json`。

## 尚未确定或未完成

- 新工程检查通过不代表真实答复质量通过。三题复测及具体缺口见 `eval/INQUIRY_RESULTS_2026-10-16_STAGE_MODELS.md`。
- 当前保存配置没有独立复核模型，本次真实试跑三个阶段都使用 GLM；更强复核模型在这些新增改动后的实际收益没有验证。
- 数字题省略 calculations 时，服务器不猜测数字的分组或含义。模型仍可能漏掉应保存的算术规格。
- 复核模型可能新增没有前提支撑的推论或返回不允许的前提字段；服务器仍拒绝这些结果，没有把它们改成通过。
- 脚注范围仍是 academic 判例；模板尚未经过 McGill 规则审阅，不包含 Word 导出等扩展。
- SQLite 的事件仍是 jsonl，小型状态仍按值保存；这不是跨对话案件库或多用户存储设计。
