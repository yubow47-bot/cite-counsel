## Bug

`_append_record()` in `core/hf_store.py` catches ANY exception from the
download-append-reupload sequence and falls through to a "create new file"
path that **unconditionally overwrites the entire remote file with just
the one new record**, silently destroying all prior history.

```python
except Exception:           # <-- catches EVERYTHING, not just "file missing"
    # File doesn't exist yet — create it
    api.upload_file(
        path_or_fileobj=line.encode(),   # <-- overwrites ALL prior data
        ...
    )
```

A transient network error, rate limit, or auth hiccup during
`hf_hub_download()` or the `upload_file` reupload would trigger this,
wiping the entire spend-tracking or feedback dataset.

## Fix

Replace `except Exception:` with `except EntryNotFoundError:`
(`huggingface_hub.utils.EntryNotFoundError` — confirmed on v0.36.2),
which is only raised when the file genuinely doesn't exist in the repo.

Any other exception (network/auth/rate-limit) now propagates to the
**outer** `try/except`, which logs a warning and returns `False` — never
overwriting existing data.

## Regression Tests

### `test_missing_file_creates_new`

Mocks `hf_hub_download` to raise `EntryNotFoundError` → asserts
`upload_file` is called once with `line.encode()` (creates new file) and
`_append_record` returns `True`. Preserves existing behavior for genuine
first-write scenarios.

### `test_transient_download_error_no_overwrite`

Mocks `hf_hub_download` to raise `ConnectionError` (NOT
`EntryNotFoundError`) → asserts `upload_file` is **never** called and
`_append_record` returns `False`. Verifies a transient network error does
NOT overwrite existing data.

### `test_reupload_failure_no_overwrite`

Mocks `hf_hub_download` to succeed (returns a real temp file), then mocks
`upload_file` to raise `RuntimeError` on the reupload → asserts that
`upload_file` was called exactly once (the failed reupload, with the local
file path) and `_append_record` returns `False`. Verifies that a transient
upload error does NOT trigger a second `upload_file` call that would
overwrite all prior data with just the new record.
