# REVIEW_REQUEST: classify_and_normalize — Constrain prompt to prevent hallucinated citation numbers on plain legislation names

_Generated by Claude Code._

---

## Problem

`classify_and_normalize()`'s LLM prompt included an unbounded rule "法条缩写：展开成完整引用（CCC → Criminal Code, RSC 1985, c C-46）" that the model applied to ANY `legislation`-type input, including plain full-name queries it was not asked to expand. For input "taxation act ontario", Gemini 2.5 Flash hallucinated a complete citation number — `"Taxation Act, 2007, SO 2007, c 11, Sch A"` — from parametric memory.

**Downstream impact:** The invented citation tokens ("SO 2007 c 11 Sch A") got glued onto the normalized title. The CanLII fallback path's residual gate correctly rejected them (they aren't in `_JURISDICTION_ARTICLE_SET`), causing `verified=False` when the statute actually exists in the database. The CanLII matching logic was working as designed — the bug was purely in the upstream prompt that let the model hallucinate.

## Fix

Tightened the prompt in `classify_and_normalize()` to:

1. **Restrict abbreviation expansion** — Only apply to KNOWN abbreviations (CCC, IRPA, CDSA, CCRF, Charter, etc.), not to plain-language full statute names.
2. **Explicit no-invented-citation rule** — For plain full-name legislation inputs, return just the cleaned title WITHOUT appending any citation number, year, chapter, or schedule.
3. **Added concrete examples** — Show both the abbreviation path (CCC → Criminal Code, RSC 1985, c C-46) and the plain-name path (Taxation Act Ontario → "Taxation Act Ontario" with no citation appended), so the model has unambiguous positive and negative examples.
4. **Added a standalone constraint sentence** — "永远不要从记忆中添加引用号、年份、章节等 citation 信息" (never add citation info from memory).

No changes to CanLII matching logic, the DeepSeek fallback path, or any other function.

## Architecture note: abbreviation-list alignment

The existing `_verify_legislation()` function in `citation_search.py` already reads from `data/normalization_rules.json`'s `legislation_abbreviations` key to perform deterministic abbreviation expansion without relying on LLM memory. A future architectural improvement would be to move classify_and_normalize()'s abbreviation-expansion responsibility into a deterministic post-LLM step that applies `normalization_rules.json` to the output, rather than asking the LLM to do it. This was not implemented here because it would require restructuring classify_and_normalize()'s return flow and adding a JSON-rule-lookup step — a larger change that deserves its own design review. The prompt-only fix is sufficient to stop the current hallucination behavior.

## Open Items

1. **Architecture: deterministic abbreviation expansion** — classify_and_normalize() currently relies on the LLM to expand known abbreviations (CCC → Criminal Code, etc.). The existing `_verify_legislation()` function and `data/normalization_rules.json` already have a deterministic abbreviation-list lookup that ground-truths the same mappings. A follow-up change could restructure classify_and_normalize() to return all legislation-type inputs as clean titles (no LLM expansion), then apply `normalization_rules.json` in a deterministic post-processing step. This would eliminate the remaining risk of LLM hallucination on abbreviation boundaries (edge cases like "CEA" → Canada Evidence Act vs. "CEA" → some other act). This is an architectural change that needs design review before implementation.

2. **Prompt test coverage gap** — Current tests mock the LLM response, so they verify the code's routing of that response but don't actually test the real model behavior against the new prompt. A regression test that calls the real Gemini API (integration test, not unit test) would be needed to confirm the model respects the new constraints. This is out of scope for unit-test-based CI but should be run manually before deploy.

3. **CanLII matching unaffected** — The reset gate in `search_citation()`'s legislation path was rejecting matches because the hallucinated citation tokens polluted `normalized`. With the prompt fix, normalized values should be clean titles, allowing the CanLII Direction-A + residual gate to match correctly. This is an indirect benefit — the matching logic was not changed.
