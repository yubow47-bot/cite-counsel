# REVIEW_REQUEST: _infer_jurisdiction_canlii — Prompt fix + model swap to Gemini 2.5 Flash

_Generated by Claude Code._

---

## Problem

Two issues in `_infer_jurisdiction_canlii()`:

1. **Prompt bug** — The LLM prompt had no instruction for genuinely ambiguous inputs. For "animal protection act" (a real Alberta statute with NO jurisdiction signal in the text), the model guessed `"ca"` (federal) instead of admitting uncertainty. This caused the CanLII fallback to search the wrong database, miss the match, and land on `_match_path="no_exact_match"` instead of `"jur_none"` — bypassing the helpful `_JUR_NONE_MSG` ("We couldn't tell which province or territory this applies to...").

2. **Provider inconsistency** — The function used DeepSeek directly while `classify_and_normalize()` had already been switched to Gemini 2.5 Flash as primary with DeepSeek fallback. This created an inconsistent provider pattern within the same module.

## Fix

### 1. Prompt rewrite
Added explicit instruction: if the input text contains NO identifiable geographic/jurisdictional signal, return `"unknown"` rather than guessing. `"ca"` should only be returned when there's an actual textual signal pointing to federal jurisdiction — never as a default.

### 2. Model swap (Gemini primary, DeepSeek fallback)
- Primary path: Gemini 2.5 Flash with `response_schema` constraint (not just `response_mime_type`), `thinkingBudget=0`, `retries=0`
- Fallback path: DeepSeek (thinking disabled) on any Gemini failure
- Return contract unchanged: valid jurisdiction code string or `None` (`"unknown"` maps to `None`)

### 3. `response_schema` enforcement
Added `_JURISDICTION_SCHEMA` - a JSON Schema constraining output to `{"jurisdiction": <enum of 14 codes + "unknown">}`. This reduces malformed-output risk compared to relying on `response_mime_type` alone.

### 4. Structured debug logging
Added `[DUR]` logging at function entry, Gemini result, fallback trigger, and exit — matching the pattern already used in `classify_and_normalize()`.

### 5. New Gemini API function
Added `call_gemini_text_structured()` in `llm_api/gemini_api.py` — takes a `response_schema` dict and returns the parsed JSON dict (or `None` on failure). Follows the same error-handling and logging pattern as `call_gemini_text()`.

## Open Items

1. **`_prescan_jurisdiction()` unchanged** — The deterministic province-name prescan still runs before the LLM, so queries with explicit province names never reach this function. Correct and unchanged.

2. **`_JURISDICTION_SCHEMA` and Gemini's schema enforcement** — The Gemini API supports `response_schema` in `generationConfig` to constrain structured output. This is an additional safety layer beyond `response_mime_type="application/json"`. If Gemini's schema enforcement is unavailable for the model (e.g., old models), it silently ignores the schema and falls back to unconstrained JSON mode — the `parse_llm_json()` + enum check catches any out-of-enum values.

3. **Spend tracker for structured call** — `call_gemini_text_structured()` uses the same model name `gemini-2.5-flash` which already has a rate entry in the spend tracker. No additional config needed.
