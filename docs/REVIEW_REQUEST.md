# Review Request: Fix thinking-disable parameter — SDK vs raw HTTP mismatch
# (Audit R1 follow-up)

_Generated by Claude Code._

---

## Bug

The initial implementation wrapped `thinking: {"type": "disabled"}` inside
an `extra_body` key, which is an OpenAI-SDK-specific wrapper. The SDK
flattens `extra_body` into the top-level JSON body before sending — but
our code builds the raw HTTP request directly (`requests` via
`request_with_retry`), so `extra_body` was sent as a literal top-level key
that DeepSeek's API does not recognize. The `thinking` instruction never
reached the server.

## Fix

Changed from:

```python
if disable_thinking:
    body["extra_body"] = {"thinking": {"type": "disabled"}}
```

to:

```python
if disable_thinking:
    body["thinking"] = {"type": "disabled"}
```

Now `thinking` is a top-level JSON key sibling to `model`, `messages`,
`temperature` — exactly what the DeepSeek HTTP API expects.
