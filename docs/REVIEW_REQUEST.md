## Context

A previously-approved implementation of year-stripped CanLII title matching
was accidentally reverted from `local_tools/citation_search.py` before it
was committed. The corresponding tests survived and are present in
`tests/test_canlii_fallback.py`:

- `test_year_stripped_single_match`
- `test_year_stripped_multi_match_degrade`
- `test_year_stripped_generalizes`

These three tests were failing with `_match_path="no_exact_match"` instead
of the expected `_match_path="year_stripped_match"`.

## Implementation

Added two things to `local_tools/citation_search.py`:

**1. Module-level regex** (near `_CITATION_SUFFIX_RE`):
```python
_TRAILING_YEAR_RE = re.compile(r',\s*\d{4}\s*$')
```

**2. Year-stripped pass** in the CanLII fallback, inside the
`elif len(matches) == 0:` block, replacing the `# else: 0 fuzzy matches`
comment with an actual `else:` block. Logic:

- For each candidate title ending with `, YYYY`, strip the year suffix
- Compare the year-stripped, normalized candidate against the query using
  the same Direction-A substring + residual-token-gate logic
- 1 match → `verified=True`, `_match_path="year_stripped_match"`
- ≥2 matches → return candidates list (same shape as Direction-A multi-match)
- 0 matches → `verified` stays `False` (falls through to existing handling)
