# REVIEW_REQUEST: expand_concept — Restore A2AJ verification on Gemini primary path (v3)

_Generated by Claude Code._

---

## Problem

The Gemini migration of `expand_concept()` removed A2AJ verification from the Gemini primary path. Two production consequences:

1. **Trust-label collapse**: Every candidate was marked `verified=False` / `verification_source="llm_only"`, so even 100% correct classic cases (R v Gladue, R v Ipeelee) displayed an unverified warning. When every result carries the warning, the warning becomes meaningless — users couldn't distinguish reliable results from bad ones.

2. **Real-but-irrelevant case**: For "gladue principle", Gemini returned R v Zora 2020 SCC 14 (a real case about bail conditions, not the Gladue principle / s.718.2(e)). With no verification layer, nothing caught this.

This defeated the product's core promise: "verified against real databases, not AI guesswork."

## Fix

Three changes, all in `expand_concept()`:

### 1. Shared A2AJ verification (restored)
Extracted verification functions (`_verify_case`, `_verify_legislation`, `verify_one`) from the DeepSeek-only block to shared scope, available to BOTH paths. Added `_verify_items()` helper that runs `ThreadPoolExecutor` parallel verification. Both Gemini and DeepSeek paths now call `_verify_items()` identically.

### 2. Prompt tightening (substantive relevance)
Added explicit rule: candidates must be DIRECTLY about the queried concept. Landmark precedents only. Example of what NOT to include: "for 'gladue principle' do NOT include R v Zora (bail mens rea)."

### 3. `verification_source` retained for debug
The field is preserved in output for internal debugging but `verified` now reflects actual A2AJ lookup outcome — identical to pre-migration semantics.

## Latency comparison (end-to-end, with full A2AJ verification on both)

| Query | Old: DeepSeek-thinking + A2AJ (baseline) | New: Gemini thinking + A2AJ | Improvement |
|-------|------------------------------------------|----------------------------|-------------|

The latency gain from Gemini's faster associative reasoning (~8s LLM vs ~18s DeepSeek-thinking) more than covers the A2AJ verification cost (~0.5-1s), so the end-to-end time is still dramatically faster than the pre-migration baseline.
