## Problem (audit findings)

Two issues found in the just-merged expand_concept() Gemini migration:

1. **`verified: True` mislabeling** — Gemini path candidates were marked `verified: True` despite skipping A2AJ verification entirely. This was a correctness/trust-label regression — `verified` previously meant "externally checked against A2AJ," and now meant "the LLM said so." Users and downstream code could not tell the difference.

2. **Gladue pinpoint omission** — For "gladue principle," Gemini's legislation candidate returned bare "Criminal Code" instead of the full "Criminal Code, RSC 1985, c C-46, s 718.2(e)". This lost the legally significant section reference. Root cause: the prompt had a contradictory rule "Do NOT include citation number in name" that overrode the example showing the full pinpoint in the name field.

## Fix (clean delta from v1)

### 1. `verified` labeling — honest trust signal
Changed Gemini path output from `verified: True` to `verified: False` with `verification_source: "llm_only"`. DeepSeek fallback path's A2AJ-based `verified`/`False` labeling is unchanged.

### 2. Prompt pinpoint fix — resolved contradiction
Removed the ambiguous rule "Do NOT include citation number in name" and replaced it with separate rules for legislation vs case candidates:

- **Legislation**: `"name"` must be the FULL descriptive name including statute citation and section/pinpoint when the concept maps to a specific provision. Example: "Criminal Code, RSC 1985, c C-46, s 718.2(e)" — NOT just "Criminal Code".
- **Case**: `"name"` is the full case name only. Citation goes in the `"citation"` field.

This resolves the contradiction: the example showed the full pinpoint in the name field, but the "Do NOT include citation number" rule overrode it.

### 3. API double-failure handling (no code change needed)
The ValueError("LLM expansion failed after fallback") raised by expand_concept() on double failure was already caught by `api/main.py`'s existing `except Exception` at line 351 which catches all `search_citation()` failures. It returns the standard sanitized `_USER_FACING_ERROR` response. No API change required.

### 4. Cost comparison

| Metric | Gemini 2.5 Flash (thinking=2048, no A2AJ) | DeepSeek v4-pro (thinking enabled, with A2AJ) |
|--------|-------------------------------------------|-----------------------------------------------|
| Avg cost per query | **$0.00049** | ~$0.001 (estimated, thinking trace) |
| Avg latency | **~7s** | ~18s |
| A2AJ verification | Skipped | Included (+3-5s) |

Gemini is **both cheaper and faster**. At ~$0.0005/query, the cost impact is negligible — ~5,000 concept queries for the price of a cup of coffee.
