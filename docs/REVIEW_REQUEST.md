# Review Request: Pinpoint duplication fixes (3 rounds)

_Generated by Claude Code._

---

## Round 1: CanLII citation-suffix stripping

**Bug**: `classify_and_normalize()` expands statute abbreviations into full
citations (e.g. `"Family Law Act"` → `"Family Law Act, RSO 1990, c F.3"`)
that `cit_match`'s regex doesn't recognize, causing CanLII title-match
failure.

**Fix**: Added `_strip_citation_suffix_for_title_match()` helper anchored to
end-of-string with `re.IGNORECASE`.

## Round 2: jurisdiction hint UX

**Bug**: When both jurisdiction prescan and LLM inference fail
(`_match_path == "jur_none"`), users saw a generic message.

**Fix**: Added `_JUR_NONE_MSG` constant and `jur_none` check in the scaffold
branch, showing a targeted hint.

## Round 3: concept-route legislation pinpoint duplicate (backend)

**Bug**: `_verify_legislation()` extracted pinpoint into `entry["pinpoint"]`
but left it embedded in `entry["name"]`, causing `format_citation()` to
include it twice.

**Fix**: When both `_pin` and `cit_match` are truthy, overwrite
`entry["name"]` with the clean base citation text.

## Round 4 (this round): redundant pinpoint field in API response

**Bug**: Even after the Round 3 backend fix, `citation_query()` and
`_handle_concept()` were still returning `pinpoint` as a separate response
field for legislation/concept routes, where the pinpoint is already
embedded in the citation text by `format_citation()`. The frontend's
`citation-card.tsx` unconditionally prefills the editable pinpoint box
whenever `item.pinpoint` is truthy, causing a duplicate on Copy.

**Fix (two changes in `api/main.py`):**

1. `citation_query()` single-result branch — changed from:
   ```python
   if _pin:
       _cit_data["pinpoint"] = _pin
   ```
   to:
   ```python
   if route == "case_name" and _pin:
       _cit_data["pinpoint"] = _pin
   ```

2. `_handle_concept()` single-result branch — removed the 3-line
   `_pin` / `_cit_data["pinpoint"]` block entirely. The pinpoint is
   never stripped before `format_citation()` in this function, so it's
   always embedded in the citation text.

**`citation_select`** verified as self-consistent: it strips pinpoint
before `format_citation()` and returns it separately — no change needed.
