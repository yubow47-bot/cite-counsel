# 从开放问题到可继续求证的答复

实现状态：2026-10-15。目标是让普通人的法律或社会问题驱动调查、推理和检查。文稿和引注是可组合能力，问题与待作出的决定才是主线。

## 能力如何重新连接

简单任务现在优先走短路径：先找出可能改变结论的少量前提，优先核查其中可由现有来源解决的未知项；读取决定性原文后调用 `inquiry__conclude`，一次提交答复、关键前提、少量关键论证、精确引语、推理和反论点回应。插件自动绑定真实回执、保存摘录与论点，并直接交付答复。复杂调查仍可逐项使用下述工具。

```text
用户问题与目标
    ↓ inquiry.frame / 可随澄清修订
会改变结论的前提：成立／不成立分别意味着什么
    ↓ 优先核查决定性未知；选择来源工具或精确补问
实际执行回执 + 精确材料版本
    ↓ research.excerpt / claim
原文、假设、前提、推论、限制和反论点
    ↓ inquiry.assess
关键论证及其所依赖的前提版本、反证回应和待查问题
    ↓ inquiry.conclude / inspect
面向用户的答复、条件、缺口与下一步
    ↓ 新材料绑定原前提；只重查受影响论点
保留原始版本，更新相关论证及答复
```

这不是强制顺序。模型可以补问、改变候选解释、重新检索或先给条件答复。一个简短澄清无需建立整套调查。可选 Skill `problem_investigation` 说明方法；方法说明不执行工具，也不提供正确性认证。

## 架构边界

- `harness/core.py` 保持通用执行循环，执行后生成回执、逐轮提供保存的任务状态，并在最终答复旁呈现插件检查。
- `harness/receipts.py` 生成模型无法通过工具参数自行制造的执行 ID，绑定工具类别、结果状态、覆盖信息与实际对象指纹。
- `core/inquiry.py` 处理问题快照、关键前提、求证任务、论证评估、答复和检查，计算前提变化影响的论点，不调用模型或外部来源。
- `plugins/inquiry/` 暴露模型工具、只读界面动作、问题面板及导出；依赖 `research`，复用已有来源和研究对象。
- `core/research.py` 与研究插件保存依据类型、适用条件、推论和证据；现有来源、提取、引语核对和引注插件继续通过精确引用组合。

Plugin 新增可选 `context_provider(ctx)` 和 `final_response_checks(ctx,text)`。前者给出有界的保存状态数据，后者返回用户可见的检查卡片。通用循环不解释法律规则，也不会偷偷将模型评估变成核验结果。

`Result.reply` 允许工具明确交付答复，省去重复总结。`inquiry__conclude`直接交付保存的确切文本；旧`answer`仅供内部兼容，已不向模型提供。检查卡比较交付文本与保存文本，输出摘要哈希；失配时显示“这份答复尚未检查”，不能把另一份答复的状态贴上来。

`Plugin.prepare_completion(ctx,text)` 只返回 `CompletionRequest` 数据，不调用模型或执行工具。Harness 的明确完成阶段最多接受一次复核，再通过与普通调用相同的 `_run_tool_call` 保存回执、模型历史与事件。`_add_caption` 只做展示。复核上下文和完整响应进入事件日志，补存工具交换进入会话历史，恢复时不再丢失这个步骤。

`TurnBudget` 统一普通请求、完成复核和工具调用的时间与次数。调查批次每次调用前检查答复预留；完成阶段另留保存余量。模型请求接受绝对截止时间和取消信号，即使不再返回数据，也能让调用方退出；迟到数据不能执行工具或改写会话。底层HTTP/DNS清理可能晚于返回；现有来源插件仍使用各自的网络超时，不能据此宣称任意阻塞插件已有硬中断能力。空模型正文报告未完成，不记成成功交付。运行预算只存在内存中，恢复或下一轮不会沿用。

工具的可选 `available(ctx)` 随配置控制实际可用性：搜索服务未配置时不向模型提供搜索，直接网页读取仍可用。

## 问题工具

| 工具 | 用途 |
|---|---|
| `inquiry__conclude` | 推荐的短路径：答复、1–3项关键检查、实际来源精确引语；每项检查可直接附关键前提，自动绑定回执并保存，直接返回答复 |
| `inquiry__frame` | 保存问题、目标、scope、关键子问题与候选解释；带 `prior_ref` 时patch澄清、新增或调整子问题 |
| `inquiry__premise` | 保存或更新一个会改变结论的前提、两种结果及下一步求证；省略ref使用本轮调查或从用户问题创建调查 |
| `inquiry__pursue` | 保存调查计划、实际 receipt IDs、发现和下一步；区分 open/investigating/resolved/blocked/inconclusive |
| `inquiry__assess` | 针对 exact research claim 保存推理检查、claim_kind、premise_ids、反证和相关回执；重新评估时绑定当前前提版本 |
| `inquiry__inspect` | 查看精确调查版本、关键阻塞、下一步和最近实际执行回执；省略ref查看当前问题 |
| `inquiry__list` | 搜索本会话已保存的问题 |

scope 包含 `jurisdiction/as_of/procedure/factual_context`。未知值明确保留；不适用时应写出理由，避免为清除警告而编造背景。修订必须基于当前版本，旧编号不会静默覆盖最新工作。改变关键背景或子问题后，旧答复与相关完成状态需要重新检查。

## 关键前提决定下一步查什么

每个重要推论先找1–3个具体前提：哪一项事实成立时答案会怎样，不成立时又会怎样。优先调查会改变建议、适用规则或主要解释的未知项。能从现有材料或公开来源核查的，模型选择相应工具主动读取；只有用户知道的个人事实，给出精确补问，并先回答当前已能回答的部分。

例如，“雇主是否属于联邦监管行业”可以改变下一步适用规则的调查方向。行业清单能说明判断标准，用户提供的工作内容能补充个案事实；仅有所在地不能自动补齐这个前提。即使行业已明确，其他影响权利的条件仍须保留。前提的真假分支用于说明影响，不表示一个前提就足以决定全部答案。

前提参数如下，`inquiry__premise` 与 `inquiry__conclude.checks[].premises[]` 使用同一组字段：

| 字段 | 用途 |
|---|---|
| `id` | 新建时省略，系统分配p1等稳定编号；补充材料时使用原编号更新 |
| `statement` | 具体待判断的条件 |
| `if_true` / `if_false` | 条件成立或不成立时，哪项结论如何改变；保留其他必要条件 |
| `next_check` | 下一份材料、具体查询、原文位置或需要用户回答的问题 |
| `method` | `source`表示查材料；`user`表示需要用户提供事实 |
| `status` | 默认`unknown`；`supported/refuted`均为有依据要求的模型判断 |
| `evidence_refs` | 实际来源Record的精确编号；插件绑定真实获取、提取或原文读取回执 |
| `user_quote` | `method=user`时使用用户真实提供的连续原话，不能用模型改写代替 |

短路径每项检查最多附3个内联前提；已有前提通过 `premise_ids` 关联，无需重复新建。`claim_kind` 区分 `direct`（窄范围原文陈述）、`inference`（依赖前提的推论）和 `hypothesis`（可能的解释）。某项比例变化可以直接计算；把变化归因于一个因素则需要额外前提和证据。不能用`direct`标签省掉这一步。

`inquiry__conclude.observations`只接受可以定位的连续原文或真实用户原话，交付时注明“来源记载／用户提供”。`calculations`必须明确提交，没有计算时为`[]`；接受变化率、差值和比值；输入数字必须完整出现在对应原文，服务器用Decimal计算，并将输入、算式、结果固定加入最终答复。计算只证明算术，不证明因果或可比性。已经验证的计算规格按当前轮保留，后续引语参数错误不会将它丢掉；收尾复用前重新校验，来源换版或新一轮不会自动沿用。旧`facts`只兼容读取模型备注，不再作为安全事实输出。

前提记录工具只保存调查状态。实际查找和阅读由模型根据 `next_steps` 选择现有工具执行。普通简短问题无需额外调用`premise`；在`conclude`里附前提即可。需要跨轮追查、更新材料或等待澄清时，再单独保存前提。

## 新材料到来后的定向重查

论证评估保存它使用的`premise_ids`、前提指纹和精确来源依赖。来源出现替代版本、前提状态或依据改变时，`inspect`只把关联论点列入`affected_claim_refs`，报告`needs_recheck`及原因。未关联论点保留原状态；一份新材料的出现本身不会使整份调查全部失效。

读取新材料后，模型用原前提`id`显式更新`evidence_refs`或用户原话，再重新评估受影响论点。更新前提并不自动接受旧推论；重新`assess`并绑定新前提快照才清除该论点的复核状态。只修改下一步检索计划，不改变前提及其依据时，也不会重开论证。

保存答复引用了受影响论点时，报告派生的`answer_needs_refresh`。检查过程不改写原答复，旧前提、旧论证和旧材料版本仍可查看。当前影响范围由显式关联决定；系统不会自动理解一份任意新文档与全部论点的语义关系。

## 实际求证与语义判断

模型描述“已查到”“无反例”不构成执行记录。回执由 `_execute_once` 在执行后产生，保存在 `Session.tool_receipts`，随会话恢复。来源、提取与可信原文字段的读取回执可用于调查；模型生成的草稿读取或自建claim不能代替来源调查。只有结构化引用字段进入输出绑定，来源正文中的 `rec_123` 字样不会制造对象引用。

回执区分 `ok/no_match/error`。一次成功读取说明材料确实可读，不说明它相关或覆盖充分。空结果不证明相关材料不存在；错误不算干净的空结果。失败历史保留，后来的成功重试可以解决执行故障，但不能擦除检索范围限制。

`inquiry.assess` 是结构化的模型评估，不是独立模型法官。它要求关键论证记录实际检查和反证处理；代码能发现未执行、缺少前提、版本变化、未回应反证及声明的范围冲突。代码不能判定任意原文是否在法律意义上足以支持推论，不能证明已经穷尽反例，也不能自动保证来源彼此独立。未来更强的语义评审仍需另行建设和验证。

前提的`source_bound`表示模型判断绑定了实际取得或读取的材料，不能据此声称其语义已证实；`user_reported`表示精确记录了用户陈述，不能升级为独立核实的事实。未找到支持、尚未查明、已找到反证分别保留，未证实不等于为假。一个解释“可以发生”也不表示它“已经发生”或“最可能发生”。答复必须在具体结论处保留这些条件，不能先作确定断言，再只在末尾加一段笼统保留。

短路径最多增加一轮有时限的模型复核，核对候选答复、关键论点、实际原文和有界任务上下文。原文上下文不仅包含模型选中的引语，也补充来源开头和实际读过／搜到的片段；每份来源最多补充5000字，去掉已在选定上下文出现的区间，避免已取得的早先例外被后来表格挤掉。最新用户问题、较早的用户澄清、保存的调查背景分开提供；截断显式标记。复核要求保留题设事实，不把细节未知误写成事实完全未知。

复核可纠正`facts/conditions/gaps`，包括把模型自加的假设误称为用户题设的情况。它还检查内联前提的两个后果分支，通过`premise_branches`指定原前提的零起始`index`并修订`if_true/if_false`；模型回显同一前提命题时也会接收两分支修订，冲突拒绝；前提原命题、状态、来源引用和用户原话保持不变。这样能纠正“另一种原因成立，所以原原因必定不存在”之类分支推断，同时不让文字复核冒充一次新的事实求证。

复核沿用用户选择的同一模型，仍可能犯语义错误，不构成独立专家审查。成功复核以哈希绑定确切候选正文，允许交付有用的条件化回答；失败、跳过或复核参数无效时只交付有归属的原文、程序计算和待查前提，不放行任意正文或条件后果分支，不自动反复重试。收尾补存使用同一次额度，不增加第二轮复核；要求简短答复、一个关键检查，避免重新输出整篇论文。同日还试验了隐藏草稿、仅根据原文重新推导；真实任务未显示可靠提升，并出现新的错误，因此未纳入默认路径。试跑记录保留，不能把架构检查通过当成语义质量通过。

读取回执必须匹配原文版本、字段、覆盖区间与切片哈希；连续或重叠分页可以联合覆盖。较晚的无关读取不会挤掉较早的有效读取。来源获取/提取回执可以证明取得确切材料版本，保留其原有类别，不能冒充“已检查整段原文”。只有不完整读取时，工具返回准确补读范围。

引语绑定仍严格：带省略号拼接的引文不能冒充连续原文。失败返回实际保存的原文修复片段，方便模型直接改用短的连续引语，绝不自动接受近似引文。完整回执及范围哈希保留在日志中；模型消息使用简短回执，避免挤掉决定性原文。重复读取同一范围会提示改用下一偏移或搜索。

## 依据类型和当前状态

研究claim新增 `basis_kind`：

- `source`：按现有行为检查是否链接支持摘录。
- `assumption`：显示为未核实的工作假设，保留结论的条件性。
- `inference`：有保存的前提与 `reasoning` 时，不机械要求直接引文；前提缺口沿路径保留。

另外保存 scope、limitations、counterargument 与 counterargument_response。支持、适用与反证回应都是声明，不能把 speaker 标记或链接存在当成法律真值。

调查论证另外报告`effective_verdict`：关联前提未知、已否定或过时时，即使原始`verdict`填写`supported`，有效状态也只能是受限判断；`hypothesis`同样不能报告有效`supported`。界面和后续上下文使用有效状态，原始判断留作审计。旧调查没有前提声明时仍能读取，并显示`premises_declared=false`；这不表示旧论证已经检查了全部必要前提。

问题报告使用：

| readiness | 含义 |
|---|---|
| `open` | 关键调查或论证检查仍有阻塞 |
| `conditional` | 无当前关键阻塞，但仍存在假设、范围限制或其他条件 |
| `ready_for_review` | 已记录工作未留下当前检查项，仍需要阅读和判断 |

所有状态始终 `legal_verification=false`、`semantic_verification=false`。新来源版本、前提修订或背景变化可以重新打开检查。检查卡绑定最终文本版本，但不评价其每句话是否由证据充分支持；文本一致、来源绑定和语义正确是不同性质的检查。

## 本轮新增的交付边界

- `direct`不由模型标签自动取得事实地位。服务器重查claim全文是否与有效支持摘录一致；不一致标为`model_interpretation`，有效`supported`降为`limited`。即使原文一致也只证明出处，始终不宣称语义已验证。
- 对当前问题给出的URL及具体前提下一步里的URL建立`source_checks`。只有真实执行回执、当前版本原文及有效指纹才算取得；`acquired`与`read`分开。首次遗漏且有预算时返回一次`needs_sources`，要求模型实际取材；失败、无工具或预算不足时在答复中保留缺口，不循环重试。
- `answer.delivery_evidence`保存验证后的观察、计算和来源检查。独立观察／计算所依赖来源换版也会打开`answer_needs_refresh`，即使来源没有链接到claim。
- 模型工具面只保留`conclude`交付新答复；旧内部`answer`入口无法放行改写正文。Harness一次收尾失败使用插件提供的安全文本，不回退未复核草稿。

这些边界让执行与算术可查。来源是否决定性、原文是否完整限定结论、推论是否遗漏前提仍需要语义判断；一次同模型复核不保证这些问题都已解决。

## 保存与界面

创建问题后会话标记 `retained=true`，跳过普通30天过期及磁盘数量上限清理，直到用户显式删除。当前仍是一份调查属于一个对话，多次轮次可以持续处理；跨对话项目资料库未实现。

问题面板展示当前目标、重要未知和下一步，详情可查看调查执行结果、原文、论证检查与保存答复。前提检查数据同时给出成立／不成立的影响、求证方法和关联论点，方便从具体缺口继续调查。只读刷新和导出不追加模型历史。导出重新检查当前依赖，保留scope、问题、回执、关键论证、条件、缺口和可读的证据快照。

## 轻量评估

离线回归检查回执伪造、来源失败与空结果、背景澄清、过时引用、未知假设与反证，以及短路径、答复时间预留、模型复核失败和自动收尾。关键前提回归另检查未知状态保留、用户原话绑定、模型自写材料被拒、原文换版、仅关联论点重开和旧档兼容。这些检查验证运行行为，不能换算为法律答复准确率；最新数量见下方评估记录。

## 设计主线与接下来建设顺序

产品目标是让开放问题变成可持续推进的调查：知道用户要作什么决定，找到可能改变结论的证据，保存推理及其条件，并在新事实出现时更新。法律引注、来源搜索、文件解析与稿件审阅都围绕这份调查组合。

当前结构分为三个边界：执行层管理资源和恢复；调查对象管理问题、事实背景、证据依赖和答复版本；插件提供来源访问、领域判断方法及可复用操作。方法可以通过 skills 改进，但执行是否发生、读到了哪里、哪份答复受到了什么检查，由系统记录。

已经接起“关键前提—实际求证—关联论点复核”的基本状态与工具。后续优先做：

1. **检查模型是否真的查了决定性未知。** 用少量完整问题观察它是否选择了有用来源、补问是否精确，以及是否及时交付条件化答复，避免只保存计划。
2. **检查正文是否保留证据边界。** 对照题设、观察、假设和推论，重点找“可能解释变成确定结论”的错误；有效状态约束和一次模型复核都不足以单独保证正文正确。
3. **验证真实更新能否少量重做。** 在已有调查中补充新材料或用户事实，检查显式前提映射和受影响论点是否准确，随后再考虑跨会话事项资料库。

每一步都以少量完整问题验收：能交付有用答复，关键依据可回查，未解决项明确，继续调查不丢状态。暂不新增多代理辩论或固定长流程。
