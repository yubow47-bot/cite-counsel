# Harness 系统复查与下一步

本轮检查覆盖模型循环、恢复与取消、来源连接器、材料覆盖、研究版本图、Skill 保留、插件接口和界面。D 盘项目只读参考，未修改或运行其中的代码，也未介入另一 agent 的工作。

## 当前实现的实际效果

材料可以保存为精确版本；摘录绑定原文区间和指纹；前提、论点、结论和草稿保存明确依赖。来源或分析被替换时，检查能沿图标记受影响成果，旧原文仍可查看。导出在下载时重新检查依赖，并保留完整的前提与证据快照。

这已能支撑个人研究工作中的“保存依据—形成分析—发现变化—重新审阅”。支持关系、说话者标签、法律解释仍是研究者或模型提出的判断。数据库来源标签表示字段来历，不能证明法律准确性、权威性或适用性。

## 本轮已修复的效果缺陷

| 缺陷 | 修复后的行为 |
|---|---|
| Crossref/OpenLibrary 超时或畸形响应显示无结果 | 结构化来源故障；真正 404 仍是无结果 |
| A2AJ 显式刷新仍读旧缓存、未建立版本替换 | 强制获取并建立 supersedes，研究依赖随新版本失效 |
| PDF 页眉文字掩盖扫描正文的缺失 | 根据图像与文本覆盖启发式补 OCR，失败保留已有文字并报告缺页 |
| 旧修订基线覆盖最新研究、修订间接依赖自身旧版本 | 返回冲突或拒绝依赖，保存前阻断 |
| 草稿漏掉深层前提证据、下载没有当前状态 | 递归快照与实时检查附录 |
| 长工具结果截掉 stale/issues；异常长编号导致摘要不结束 | 保留关键状态并限制序列化大小；有界编号和终止后备路径 |
| 摘录默认字段与文档实际字段不同，导致无谓失败 | 默认选择已有正文类型字段；明确指定错误字段时仍报错并列出可用字段 |
| 引用的工具标记被执行 | 只恢复整条消息完全由工具协议组成的调用 |
| 收尾绕过时间预算、排队请求取消后仍运行 | 预算覆盖收尾；按取消代次拒绝旧排队请求 |
| 首轮请求及完成的工具只在整轮结束才保存 | 首次模型调用前、每个已完成工具后 checkpoint；重启补齐中断回执 |
| 磁盘写入失败只写日志 | 界面明确警告仅保存在内存，重试成功后清除 |
| 刷新研究目录污染模型历史、Skill 被长历史裁掉 | 插件可声明只读 action；已打开的可用 Skill 保留 |
| 异步恢复、材料读取、上传可能串到别的会话 | 请求代次与会话校验，上传串行并暂时锁定切换 |
| 工作区被设置和完整 JSON/哈希占满 | 独立设置弹窗、分类材料、精简研究卡片、窄屏抽屉 |

## 轻量验证与实用性判断

离线测试检查真实保存对象、导出和恢复结果；四条脚本工作流继续作为快速集成 smoke。采用 [Harvey Labs 架构](https://github.com/harveyai/harvey-labs/blob/main/docs/architecture.md) 中任务、产物、轨迹与评分分开的思路，保持本项目评估很小。[Anthropic 的 agent 评估建议](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)也强调检查最终环境状态及执行轨迹。脚本通过不能代表模型法律能力。

另做两次仅使用合成材料的有界模型试跑：第一次使用默认设置的 Qwen，误把备忘录写入引注元数据，没有完成保存研究对象的任务。随后明确工具目录中的 load 入口、可用工具和 metadata 工具边界；使用 Harness 保存配置的 GLM 试跑，完成三份摘录、前提、论点、修订结论、草稿与检查。它仍触及人为设置的八轮预算，并出现需要自行修正的调用。这只能证明这条小流程可运行；模型间工具选择和调用效率仍不稳定，不能据此宣称通用任务已可靠。

本地报告位于 `.chatbox-runtime/usability-probe/`；默认被 Git 忽略，只含本轮合成会话。完整法律质量评测暂不扩张。

最终验证：Python 离线回归 **503 passed / 7 skipped**（两个依赖弃用警告）；Node 前端回归 **6/6**；离线端到端 smoke **4/4**。浏览器实际检查了桌面与 390px 布局、设置弹窗、精确原文与分页、新会话后恢复、抽屉关闭；控制台无错误。截图在 `.chatbox-runtime/round2-workspace.jpg` 与 `round2-mobile.jpg`。后端改动需要重启正在运行的 Harness 进程；验收使用隔离服务，没有重启用户原有服务。

## D 盘 Ibid / supra 的迁移判断

只读检查 `D:\mcgill\core\footnotes.py` 与 `docs/PHASE2_FOOTNOTE_REFERENCES.md`。现有 `preview_footnotes` 已按完整顺序重算首次完整引注、Ibid 和 supra，处理空脚注、多来源中断、简称缺失以及来源 revision。当前范围是 academic 判例预览，不能直接当成持久文稿管理器。

建议新增独立 `footnotes` 功能插件，与 bibliography 并列，依赖 McGill 渲染与规则。McGill 的无序完整引注仍保留原职责。脚注插件持久保存：

- 文档 ID、revision、引用模式和规则版本；
- 稳定的 note/occurrence ID 与完整脚注顺序；
- 精确材料编号、作品身份、来源指纹、明确简称与 pinpoint 绑定；
- 写入使用 expected_revision 与 request_id，避免并发覆盖及重试重复。

增删移动脚注后，以确定性函数重算整篇引用。来源更新应标记待审阅，不能静默把文稿中的固定旧版本替换为新版本。初版先实现现有规则范围的完整/短引、Ibid、supra，不扩展到任意文档格式或所有法域。复杂简称冲突、多权威同注、首引删除、重试/并发及来源变化应成为它自己的少量核心回归。

## 接下来优先建设什么

1. **把变化处理做顺手**：从 stale 问题直接进入旧新原文对照，展示受影响路径，让研究者逐级修订；当前只能请 agent 重建并重新关联。
2. **脚注序列插件**：使用上述独立文档对象，在引用顺序可控的范围内可靠实现 Ibid / supra。
3. **从现有草稿提取审阅对象**：导入一小段用户草稿，把论点、引语与引用变成可审阅对象；先展示遗漏与疑点，不生成笼统的“通过”。

[Westlaw Quick Check 的公开说明](https://www.thomsonreuters.com/en-us/help/westlaw-edge/tools/quick-check)启发的是把文稿审阅组织成可定位的问题和原文对照。本项目没有其专有权威库、KeyCite 或完整后续判例状态，不能把本地证据图检查描述成这些能力。

实施仍需注意：PDF 路由依赖启发式，OCR 可错；来源 API 可能过期/限流；单机 JSON checkpoint 并非多用户事务服务；模型的 supports/opposes 标签并不自动成立。优先把已有材料和分析的变化暴露给人，再扩张插件数量。
