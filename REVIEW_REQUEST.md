## Goal

Add image & scanned-PDF input support via Kimi (Moonshot) vision model for Tab2 file extraction, compensating for Tab3 URL extraction failures when news/article pages are blocked by anti-scraping. Users can upload a screenshot and get the same structured fields as the URL path, with zero changes to the downstream `classify_document_type` → `format_citation` pipeline.

## Risk Declaration

* Kimi vision API is a **paid external service** with no local fallback — if the API key is missing or exhausted, image/scanned-PDF extraction degrades to `{"error": "..."}` which triggers the manual scaffold (graceful, but not transparent to the user).
* PDF scanned detection uses a fixed `SCANNED_THRESHOLD=50` character count — PDFs with decorative text (headers/footers/logos) > 50 chars but no body text will be misclassified as text PDF and produce garbled output.
* The `_extract_pdf_scanned` function creates temp PNG files (`{file_path}.page{i}.png`) and cleans them in `finally` — if the process is killed mid-flight, temp files may leak.
* Base64-encoded image payloads can be large (~MB per image) — with 3 pages at 200 DPI, the request may approach token limits for `moonshot-v1-8k-vision-preview`.
